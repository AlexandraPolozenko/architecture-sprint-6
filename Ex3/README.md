# architecture-sprint-6

Текущие проблемы:
- При запросе информации о продуктах СК микросервис ins-product-aggregator идет синхронно в апи всех страховых компаний, соответственно зависит от их скорости ответа и их количества (с ростом числа СК повышается и время ответа апи)
- При недоступности хотя бы одного апи, ответ не удастся получить.
- Рискуем, что данные в core-app и ins-comp-settlement будут неконсистентны из-за разных интервалов обновления


Предлагается использовать паттерн Transactional Outbox
Это поможет:
- Гарантировать доставку событий
- Атомарно сохранять данные и публиковать события
